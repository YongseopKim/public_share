### 판단 필요 지점

```
판단 필요 지점을 만났을 때

A. 멈춤
    엔진 --X  판단 필요 지점으로 기록 ---------------------> [2]로
    보고서: 추론이 안 섞임. 대신 지금 사건은 거기서 멈춤

B. 제안
    엔진 --> LLM이 다음 조회 제안 --> 엔진이 조회 --> 계속 추적
    보고서: 더 멀리 가지만, 틀린 판단이 사실과 구분 없이 섞임

C. 제안 + 표시
    엔진 --> LLM이 다음 조회 제안 --> 엔진이 조회 --> 계속 추적
            |                          보고서: 이 구간은 "추론 구간"으로 따로 표시
            +--> 선택을 사건 기록에 남김
            +--> 그 지점은 [2]로
```

### PoC

#### 목표

"털렸다" 한마디에서 시작해 접수 에이전트가 대화로 피해 거래까지 갈 수 있는지 확인하는 것이 목표.
- 피해자 역할: 팀원이 공개 사건 3건을 들고 피해자 역할을 함
- 만들지 않는 것: 권한 조회와 취소 안내, 공격 유형 판정, 유료 라벨, 쉬운 말 요약, 수사관 화면, 질의 에이전트, 패턴 작성 에이전트, 감시 작업, events 기록과 재생

### MVP

#### 목표

실제 피해자 한 명이 처음부터 끝까지 혼자 쓸 수 있는 최소한을 만드는 것을 목표

위의 PoC에 추가적으로 더해지는 것들
- 권한 조회와 취소 안내
- 공격 유형 판정
- 유료 라벨 규칙
- 쉬운 말 요약, 결과 화면, 사건 파일 내려받기
- 판단 필요 지점: 멈추고 목록에 기록("판단 필요 지점" 그림의 A안)
- 백엔드: 작업 실행기, Postgres, events 기록

목표로 하는 to-be와 비교해서 아직 하지 않는 것들
- 패턴 작성 에이전트: 판단 필요 지점 목록 관련 데이터가 쌓여야 함
- 질의 에이전트와 수사관 화면: 현재는 실제 수사관이 없음
- 감시 작업과 텔레그램 알림: 관련 데이터가 쌓여야 함

```
  |    공격 유형: 원장으로 판정되면 엔진 규칙, 안 되면 "피해자 진술"로 기록 |
  |    원장과 진술이 어긋나면: 확정하지 않고 사람이 검토                  |
  |                                                                    |
  |  에이전트에게 주는 것: 맡길 일, 쓸 수 있는 도구, 대화 횟수와 시간 상한 |
  |  에이전트에게 받는 것: 정해진 형식의 결과 + "다음 단계로 가도 됨" 제안 |
  +--------------------------------------------------------------------+
```

#### 그림 2. 추적 엔진 속

```
  +--------------------------------------------------------------------+
  | 추적 엔진 (결정적 코드)                                             |
  |                                                                    |
  |  조회 도구 (에이전트는 사건 서비스를 거쳐서만 씀)                    |
  |    - 후보 거래 조회: 지갑에서 나간 거래 목록                          |
  |    - 공격 유형 판정 규칙: approve, permit                            |
  |    - 권한 조회: 살아 있는 approve, permit 권한                       |
  |                                                                    |
  |  본 추적                                                            |
  |    피해 거래 --> 패턴 카드로 갈래 분류 --> 동결 창 탐지               |
  |                     |                                              |
  |                     +-- 이름 모르는 끝점 --> 유료 라벨 규칙          |
  |                     +-- 판단 필요 지점 --> 멈추고 목록에 기록         |
  |                     +-- 추적 종료 지점 --> 기록                       |
  |                                                                    |
  |  사건 파일 생성기: 숫자, 주소, 해시, 시각은 사건 JSON에서 그대로 넣음  |
  +--------------------------------------------------------------------+
```

#### 그림 3. 백엔드 구성

```
  웹 화면
    |  HTTPS (대화는 스트리밍)
    v
  +--------------------------------------------------------------------+
  | API 서버 (FastAPI)                                                  |
  |   피해자 API                                                         |
  |   사건 서비스: 상태 전이 함수                                         |
  |     (지금 상태, 들어온 사건) -> (새 상태, 할 일 목록)                   |
  |   접수 에이전트 대화: 대기열을 거치지 않고 여기서 바로 스트리밍          |
  +--------------------------------------------------------------------+
        |  할 일을 작업 대기열에 넣음               ^  결과를 사건으로 돌려줌
        v                                         |
  +--------------------------------------------------------------------+
  | 작업 실행기 (worker)                                                 |
  |   추적 작업 ---------> 추적 엔진 (Python 패키지)                      |
  |   결과 작성 작업 ----> 사건 파일 생성기 + 쉬운 말 요약                  |
  +--------------------------------------------------------------------+

  에이전트 실행기: 역할 설정은 접수 에이전트 하나
    역할 설정 = 시스템 프롬프트 + 허용 도구 목록 + 결과 형식 + 상한
    도구 = 후보 거래 조회, 권한 조회, report_result (사건 번호는 서비스가 고정)

  사건 저장소 (Postgres)
   - cases:     사건별 현재 상태
   - events:    상태 전이, 에이전트의 도구 호출 (추가만 하고 고치지 않음)
   - messages:  대화 기록
   - artifacts: 사건 JSON, 사건 파일
```
