```text
[원본 체인]  잔돈 USDC가 있다
     |
     |  관문 1: 꺼내려면 이 체인에서 tx가 필요하다
     |    보통  이 체인의 네이티브 가스(ETH 등)가 지갑에 있어야 한다
     |    기획  사용자는 서명만 하고, tx와 가스는 릴레이어가 맡는다
     v
[체인 사이]
     |
     |  관문 2: 다른 체인으로 옮겨야 한다

     |    기획  CCTP로 소각하고 같은 양을 재발행한다
     |          도착 체인의 발행 tx는 Circle Forwarding이 대신 낸다 (0.05 USDC)
     v
[도착 체인 Arc]
     |
     |  관문 3: 받은 돈을 쓰려면 또 가스가 필요하다
     |    보통  도착 체인의 가스 토큰을 따로 구해야 한다
     |    기획  Arc에서는 USDC가 곧 가스다. 받은 USDC로 바로 쓴다
     v
[바로 사용]  Arc 앱, 기부로 남기는 첫 트랜잭션, 거래소로 출금
```

```text

       |
(2) 잔고 조회    같은 주소로 v1 체인(Ethereum, Base, OP, Arbitrum)의 USDC를 본다
       |
(3) 체인 선택    모을 체인을 고른다. 금액이 너무 작은 체인은 대기로 빠진다
       |

       |

       |
```

## 기능 1 USDC 모으기: 사용자는 서명만 하고 운영자는 USDC를 보관하지 않는다

```text
범례   ==>  USDC가 움직인다
       -->  서명이나 메시지가 전달된다

[원본 체인]  아래 (1)과 (2)를 체인마다 한 번씩 한다

  사용자 지갑 --(1) ERC-3009 서명--> 릴레이어
                                        |
                                        | (2) 트랜잭션 1개를 올리고 가스를 낸다
                                        v
  스위퍼 컨트랙트: a, b, c가 한 트랜잭션 안에서 일어난다
    a. receiveWithAuthorization : 사용자 지갑 ==> 컨트랙트
    b. 수수료 분기              : 컨트랙트 ==> 트레저리 (차감 방식일 때만)
    c. depositForBurn           : 나머지 USDC를 소각, 수령인 = 서명자 주소
                                        |
                                        | (3) 소각 메시지
  - - - - - - - - - - - - - - - - - - - | - - - - - - 체인 경계
[Circle]                                v
  attestation --> Forwarding이 Arc에서 재발행 트랜잭션을 낸다
                                        |
                                        | (4) 건당 0.05 USDC
  - - - - - - - - - - - - - - - - - - - | - - - - - - 체인 경계
[Arc]                                   v
  서명자와 같은 주소 <== 소각한 양만큼 USDC가 재발행된다
```

```text
범례  U  사용자 지갑
      R  릴레이어, 운영자 서버
      S  스위퍼 컨트랙트, 운영자가 체인마다 배포
      T  트레저리, 운영자 금고
      C  Circle
      A  Arc에 있는 같은 주소
      --> 서명이나 메시지가 간다
      ==> USDC가 움직인다

           U      R      S      T      C      A
           |      |      |      |      |      |
 (1)       |-sig->|      |      |      |      |   사용자는 서명만 한다. 가스 0
           |      |      |      |      |      |
 (2)       |      |-tx-->|      |      |      |   R이 tx 1개를 올리고 가스를 낸다
        +--|------|------|------|--+   |      |
        |a |=============>      |  |   |      |   USDC가 지갑에서 S로
        |b |      |      |=====>|  |   |      |   실비만 T로. 차감 방식일 때만
        |c |      |      |burn  |  |   |      |   나머지를 소각. 받는 주소 = U
        +--|------|------|------|--+   |      |   a, b, c는 한 tx 안에서 일어난다
           |      |      |      |      |      |
 (3)       |      |      |---burn msg->|      |   Circle이 소각을 확인한다
           |      |      |      |      |      |
 (4)       |      |      |      |      |=mint>|   Forwarding이 Arc에서 발행, 0.05 USDC
```

```text
[기존 방식: 브리지, Across의 경우]

출발 체인
  사용자 지갑: 10 USDC
      |  (1) 사용자가 예치 tx를 올린다. 가스는 사용자가 ETH 등으로 낸다
      v
  브리지 컨트랙트: 10 USDC가 잠긴다
      |  (2) 예치 사실이 알려지고, 릴레이어가 이를 본다
- - - | - - - - - - - - - - 체인 경계
도착 체인
      v
  릴레이어가 자기 USDC로 먼저 보낸다
      |  (3) 사용자는 여기서 바로 받는다
      v
  사용자 주소: 10 - 릴레이어와 유동성 공급자 몫

그 뒤
  (4) 정산: 잠겨 있던 10 USDC로 릴레이어에게 갚는다
      약 1.5시간마다 묶어서 처리하고, 사용자는 기다리지 않는다
```

```text
[아이디어 방식: CCTP]

출발 체인
  사용자 지갑: 10 USDC
      |  (1) 사용자는 서명만 한다. tx와 가스는 릴레이어가 맡는다
      v
  스위퍼 컨트랙트: 받자마자 10 USDC를 소각한다
      |  (2) 소각 메시지가 간다. 출발 체인의 확정을 기다린다 (5분 ~ 15분)
- - - | - - - - - - - - - - 체인 경계
Circle
      v
  소각을 확인한다 (attestation)
      |  (3) Forwarding이 도착 체인에 발행 tx를 낸다
- - - | - - - - - - - - - - 체인 경계
도착 체인 Arc
      v
  사용자 주소: 10 USDC가 새로 발행된다. Forwarding 0.05만 빠진다

그 뒤
  (4) 없다. 먼저 돈을 낸 사람이 없으니 갚을 일도 없다
```

```text
범례  B = 기존 방식: 브리지나 스왑을 거친다 (예: Across)
      C = 아이디어 방식: CCTP 소각과 재발행

출발 체인의 USDC는
  B | 브리지 컨트랙트에 맡겨진다 (잠김)
  C | 소각되어 없어진다

도착 체인의 USDC는 어디서 나오나
  B | 릴레이어가 미리 가진 자기 USDC로 먼저 준다
  C | Circle이 새로 발행한다

받는 양
  B | 보낸 양 - 릴레이어와 유동성 공급자 몫. 경로에 스왑이 끼면 슬리피지도
  C | 소각한 양 그대로. Forwarding 요금만 빠진다

수수료를 받는 쪽
  B | 돈을 먼저 대는 릴레이어와 유동성 공급자
  C | Standard 전송은 프로토콜 수수료 0. Fast 전송만 Circle에 수수료

기다리는 이유
  B | 릴레이어가 먼저 주므로 사용자는 정산을 기다리지 않는다
  C | Standard는 출발 체인의 확정을 기다린다 (원문 5분 ~ 10분, 프로토타입 ~15분)

출발 체인의 가스
  B | 사용자가 그 체인의 네이티브 토큰으로 낸다 (원문의 지적)
  C | 아이디어에서는 릴레이어가 낸다. CCTP 자체의 특징은 아니다
```

## 기능 2 잡토큰 회수: 기능 1과 무엇이 다르고 왜 미루는가

```text
범례  q+  스왑 견적이 있는 토큰
      q-  팔 수 없는 토큰. 회수 대상에서 뺀다
      w   실비가 토큰 가치의 30%를 넘는 토큰. 대기로 돌린다
      ==> 토큰이나 USDC가 움직인다
      [!] 실패할 수 있는 곳

[원본 체인 하나]  체인마다 아래를 한 번씩 한다

  사용자: 승인, 스왑, 소각 내용을 보고 서명 (EIP-7702 지갑 위임)
          |
          v
  token A  q+ ==swap==> USDC --+
  token B  q+ ==swap==> USDC --+      [!] 견적 만료: 아무것도 움직이지 않는다
  token C  q-   x              |      여기까지는 토큰마다
  token D  w    x              |
                               v
                         USDC 합계
                               |      실비를 결과 USDC에서 뺀다
                               v
                         CCTP burn    여기는 체인마다 1회
                               |
- - - - - - - - - - - - - - - -|- - - - 체인 경계
[Circle]                       v
                         attestation  [!] CCTP 지연: 소각은 끝났고 아직 도착 전
                               |
- - - - - - - - - - - - - - - -|- - - - 체인 경계
[Arc]                          v
                     mint (Forwarding) ==> 같은 주소
```

```text
범례   1 = 기능 1, 흩어진 USDC 모으기
       2 = 기능 2, 잡토큰 회수

옮기는 것
  1 | 이미 USDC인 잔액
  2 | 스왑 견적이 있는 소액 토큰. 원본 체인에서 USDC로 바꾼다

사용자가 하는 일
  1 | 체인마다 ERC-3009 서명 한 번
  2 | 승인, 스왑, 소각 내용을 지갑에서 확인하고 서명 (EIP-7702 지갑 위임)

Arc로 보내는 방법
  1 | CCTP 소각과 Forwarding 재발행, 체인마다
  2 | 스왑한 뒤 체인당 한 번 CCTP

요금
  1 | 무료(후원)가 기본. 가스가 비싸면 차감 또는 대기
  2 | 실비 차감으로 고정. 서비스 수수료 없음, DEX 수수료는 화면에 보인다

실패할 수 있는 곳
  1 | 서명 만료, CCTP 지연
  2 | 위의 둘에 더해 스왑 실패, 팔 수 없는 토큰

일정
  1 | 먼저 만든다 (8주 계획의 1주차부터 4주차)
  2 | 상위 토큰만, 시뮬레이션과 한도를 붙여 나중에 (5주차부터 6주차)
```
