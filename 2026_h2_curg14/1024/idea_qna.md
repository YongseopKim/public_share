# 근탁님 아이디어 정리

## overall

```text
[원본 체인]  잔돈 USDC가 있다
     |
     |  관문 1: 꺼내려면 이 체인에서 tx가 필요하다
     |    보통  이 체인의 네이티브 가스(ETH 등)가 지갑에 있어야 한다
     |    기획  사용자는 서명만 하고, tx와 가스는 릴레이어가 맡는다
     v
[체인 사이]
     |
     |  관문 2: 다른 체인으로 옮겨야 한다
     |    보통  브리지 수수료를 낸다. 경로에 스왑이 끼면 슬리피지도
     |    기획  CCTP로 소각하고 같은 양을 재발행한다
     |          도착 체인의 발행 tx는 Circle Forwarding이 대신 낸다 (0.05 USDC)
     v
[도착 체인 Arc]
     |
     |  관문 3: 받은 돈을 쓰려면 또 가스가 필요하다
     |    보통  도착 체인의 가스 토큰을 따로 구해야 한다
     |    기획  Arc에서는 USDC가 곧 가스다. 받은 USDC로 바로 쓴다
     v
[바로 사용]  Arc 앱, 기부로 남기는 첫 트랜잭션, 거래소로 출금
```

```text
(1) 지갑 연결    사용자가 자기 지갑을 연결한다. 키는 서비스에 가지 않는다
       |
(2) 잔고 조회    같은 주소로 v1 체인(Ethereum, Base, OP, Arbitrum)의 USDC를 본다
       |
(3) 체인 선택    모을 체인을 고른다. 금액이 너무 작은 체인은 대기로 빠진다
       |
(4) 서명         고른 체인마다 지갑에서 ERC-3009 서명을 한 번씩 한다
       |
(5) 처리         릴레이어가 체인마다 tx를 올리고, CCTP와 Forwarding이 옮긴다
       |
(6) 도착         서명한 사람과 같은 주소로 Arc에 USDC가 들어온다
```

## 용어: 릴레이어 서버, 스위퍼 컨트랙트, 트레저리

**릴레이어 서버**: 사용자 대신 트랜잭션을 올려 주는 우리가 구현해야 할 서버
- 하는 일: 사용자의 ERC-3009 서명을 받아 원본 체인에 tx를 올리고 가스를 낸다. 그래서 체인마다 그 체인의 가스 토큰을 넣어 둬야 한다.
- 못 하는 일: "제출하거나 안 하거나"만 할 수 있다. 금액, 만료, 받는 컨트랙트가 서명에 고정되어 있다.
- 우리 릴레이어는 돈을 대지 않고 tx와 가스만 맡는다.
- 참고: 서명을 대신 제출하는 서버를 이더리움에서는 보통 메타 트랜잭션 릴레이어라고 부른다(예: Gelato Relay, OpenZeppelin Defender의 Relayer)

**스위퍼 컨트랙트**: 우리가 체인마다 배포하는, 잔돈을 모으는 컨트랙트. 받고(`receiveWithAuthorization`), 처리 비용을 떼고(차감 방식일 때), 소각한다(`depositForBurn`). 셋이 한 tx 안에서 일어난다.
- 성질: "관리자 키 없음·업그레이드 불가", "팀도 릴레이어도 자금 이동 권한 없음". 우리가 USDC를 보관하지 않는다는 주장은 이 성질에 기댄다.
- 스위퍼: sweep(쓸어 모으다). Jumper의 "Dust Sweeper". QuickNode의 "Token Sweeper".
- 참고: 업계에서 "sweeper bot"은 키가 유출된 지갑에 들어오는 돈을 곧바로 빼 가는 악성 봇을 가리킨다.

**트레저리**(treasury): 우리의 USDC 금고, 곧 우리가 가진 지갑 주소
- 공개 회계로 보여 주고, 차감으로 받은 돈은 "수입"이 아니라 비용을 메운 것으로 표시한다
- 차감은 원본 체인에서 일어나므로 원본 체인에도 트레저리 주소가 있어야 한다
- 참고: 프로젝트나 DAO가 공동 자금을 두는 지갑을 보통 이렇게 부른다.

## 기능 1 USDC 모으기: 사용자는 서명만 하고 운영자는 USDC를 보관하지 않는다

```text
범례  U  사용자 지갑
      R  릴레이어, 운영자 서버
      S  스위퍼 컨트랙트, 운영자가 체인마다 배포
      T  트레저리, 운영자 금고
      C  Circle
      A  Arc에 있는 같은 주소
      U, R, S, T는 원본 체인에, A는 도착 체인 Arc에 있다
      --> 서명이나 메시지가 간다
      ==> USDC가 움직인다
      처리 비용 = 원본 체인의 릴레이어 가스 + Arc의 Forwarding 요금
      프로토타입은 실비, 메시지는 수수료라고 부른다 (h:81, t:68)

(1)과 (2)는 모을 체인마다 한 번씩 한다

           U      R      S      T      C      A
           |      |      |      |      |      |
 (1)       |-sig->|      |      |      |      |   ERC-3009 서명. 사용자는 가스 0
           |      |      |      |      |      |
 (2)       |      |-tx-->|      |      |      |   R이 tx 1개를 올리고 가스를 낸다
        +--|------|------|------|--+   |      |
        |a |=============>      |  |   |      |   receiveWithAuthorization: 지갑에서 S로
        |b |      |      |=====>|  |   |      |   수수료 분기: 처리 비용만 T로. 차감 방식일 때만
        |c |      |      |burn  |  |   |      |   depositForBurn: 나머지를 소각. 받는 주소 = U
        +--|------|------|------|--+   |      |   a, b, c는 한 tx 안에서 일어난다
           |      |      |      |      |      |
 (3)       |      |      |---burn msg->|      |   Circle이 소각을 확인한다 (attestation)
           |      |      |      |      |      |
 (4)       |      |      |      |      |=mint>|   Forwarding이 Arc에서 소각한 양만큼 재발행, 건당 0.05 USDC
```

## 우리가 만드는 부분: 스위퍼 컨트랙트

스위퍼 컨트랙트
- Circle이나 Arc가 제공하는 것이 아니라, 우리 팀이 직접 작성해서 체인마다 배포하는 컨트랙트

```text
범례  W  우리가 만들고 운영한다
      C  Circle이 만들고 운영한다
      U  사용자의 지갑. 우리 것도 Circle 것도 아니다
      A  도착 체인 Arc
      --call-->  스위퍼가 다른 컨트랙트의 함수를 부른다

  만드는 쪽
  |
  W   (1) 웹 화면
  |       지갑 연결, 잔고 조회, 서명 요청
  U   (2) 사용자 지갑
  |       ERC-3009 서명을 한다. 키는 지갑 밖으로 나가지 않는다
  W   (3) 릴레이어 서버 R
  |       서명을 받아 tx를 올리고 가스를 낸다
  W   (4) 스위퍼 컨트랙트 S, 모을 체인마다 배포
  |         a --call--> C   USDC 토큰 컨트랙트의 receiveWithAuthorization
  |         b           W   트레저리 T로 처리 비용을 보낸다. 차감 방식일 때만
  |         c --call--> C   CCTP TokenMessengerV2의 depositForBurn
  C   (5) attestation과 Forwarding
  |       소각을 확인하고 Arc에서 재발행 tx를 낸다
  A   (6) Arc의 같은 주소
          서명자 본인이 USDC를 받는다
```

| 부분                    | 만드는 쪽 | 하는 일                                         |
| ----------------------- | --------- | ----------------------------------------------- |
| 웹 화면                 | 우리      | 지갑 연결, 잔고 조회, 서명 요청, 완료 화면      |
| 릴레이어 서버 R         | 우리      | 서명을 받아 tx를 올리고 가스를 낸다             |
| 스위퍼 컨트랙트 S       | 우리      | a, b, c를 한 tx 안에서 실행한다                 |
| 트레저리 T              | 우리      | 차감한 처리 비용과 Arc에서의 잔돈 기부를 받는다 |
| 투명성 대시보드         | 우리      | 트레저리 회계를 온체인 기록으로 공개한다        |
| USDC 토큰 컨트랙트      | Circle    | ERC-3009 서명으로 USDC를 옮긴다                 |
| CCTP TokenMessengerV2   | Circle    | `depositForBurn`으로 USDC를 소각한다            |
| attestation, Forwarding | Circle    | 소각을 확인하고 Arc에서 재발행 tx를 낸다        |
| Arc                     | 도착 체인 | USDC를 받고, 그 USDC가 곧 가스다                |

우리가 만드는 것: 다섯 가지
1. 웹 화면
2. 릴레이어
3. 스위퍼 컨트랙트
4. 트레저리
5. 대시보드

프로토타입
- A: 컨트랙트 -> 배포 -> ...
- B: 릴레이어 -> UI와 서명 -> ...

## 사비로 운영할 때의 비용: 1인당 비용과 사용자 수

아래 비용은 모두 무료(후원) 방식일 때 운영자가 내는 돈이다. 차감 방식이면 운영자 부담은 거의 없다.

---

> 비용이 체인당 대략 0.06 달러입니다. L2 가스 0.001 + Forwarding 0.05 + Arc 가스 0.002

```text
(가) 체인 하나를 옮기는 처리 비용, 프로토타입 모형, 단위 달러

  열   (a) 릴레이어 가스 = 가스가 x 200,000 gas x 가스 토큰 가격
       (b) Forwarding
       (c) 합계 = (a) + (b)

                    (a)          (b)          (c)
  OP Mainnet      0.0006   +   0.052    =   0.0525
  Base            0.0033   +   0.052    =   0.0553
  Polygon PoS     0.0059   +   0.052    =   0.0579
  Arbitrum        0.0110   +   0.052    =   0.0630
  Ethereum        0.1595   +   0.052    =   0.2115
```

> 사용자 한 명이 3개 체인 모으면 저희 부담이 0.18달러 정도

```text
(나) 사용자 한 명이 여러 체인을 모을 때, 단위 달러

  열   (d) 모은 체인    (e) 모형 합계    (f) 작성자가 적은 값

       (d)                              (e)       (f)
  A    Base + OP + Arbitrum             0.1709    0.17, 0.18
  B    A + Ethereum                     0.3823    -
  C    A + Polygon PoS                  0.2288    -
  D    A + Ethereum + Polygon PoS       0.4403    0.45 정도
```

---

운영자가 언제 내는가

```text
처리 비용 = 릴레이어 가스 + Forwarding 0.052
위에서부터 차례로 보고, 처음 맞는 줄을 따른다

  1  cost > amt x 30%                대기. 옮기지 않는다
  2  cost <= min($0.30, amt x 10%)   무료. 운영자가 낸다
  3  not L1 (L2)                     무료. 비용과 상관없이 운영자가 낸다
  4  else                            차감. 사용자의 USDC에서 뺀다

  cost = 처리 비용
  amt  = 그 체인에서 옮길 USDC 금액
```

## 기능 2 잡토큰 회수: 기능 1과 무엇이 다르고 왜 미루는가

```text
범례  q+  스왑 견적이 있는 토큰
      q-  팔 수 없는 토큰. 회수 대상에서 뺀다
      w   처리 비용이 토큰 가치의 30%를 넘는 토큰. 대기로 돌린다
      ==> 토큰이나 USDC가 움직인다
      [!] 실패할 수 있는 곳

[원본 체인 하나]  체인마다 아래를 한 번씩 한다

  사용자: 승인, 스왑, 소각 내용을 보고 서명 (EIP-7702 지갑 위임)
          |
          v
  운영자: tx를 올리고 가스를 먼저 낸다. 뒤에서 결과 USDC로 돌려받는다
          |
          v
  token A  q+ ==swap==> USDC --+
  token B  q+ ==swap==> USDC --+      [!] 견적 만료: 아무것도 움직이지 않는다
  token C  q-   x              |      여기까지는 토큰마다
  token D  w    x              |
                               v
                         USDC 합계
                               |      DEX 수수료와 처리 비용을 뺀다
                               v
                         CCTP burn    depositForBurnWithHook, 체인마다 1회
                               |
- - - - - - - - - - - - - - - -|- - - - 체인 경계
[Circle]                       v
                         attestation  [!] CCTP 지연: 소각은 끝났고 아직 도착 전
                               |
- - - - - - - - - - - - - - - -|- - - - 체인 경계
[Arc]                          v
                     mint (Forwarding) ==> 같은 주소
```

```text
범례   1 = 기능 1, 흩어진 USDC 모으기
       2 = 기능 2, 잡토큰 회수

옮기는 것
  1 | 이미 USDC인 잔액
  2 | 스왑 견적이 있는 소액 토큰. 원본 체인에서 USDC로 바꾼다

사용자가 하는 일
  1 | 체인마다 ERC-3009 서명 한 번
  2 | 승인, 스왑, 소각 내용을 지갑에서 확인하고 서명 (EIP-7702 지갑 위임)

Arc로 보내는 방법
  1 | CCTP 소각과 Forwarding 재발행, 체인마다
  2 | 스왑한 뒤 체인당 한 번 CCTP

요금
  1 | 무료(후원)가 기본. 가스가 비싸면 차감 또는 대기
  2 | 처리 비용 차감으로 고정. 서비스 수수료 없음, DEX 수수료는 화면에 보인다

실패할 수 있는 곳
  1 | 서명 만료, CCTP 지연
  2 | 위의 둘에 더해 스왑 실패, 팔 수 없는 토큰

일정
  1 | 먼저 만든다 (8주 계획의 1주차부터 4주차)
  2 | 상위 토큰만, 시뮬레이션과 한도를 붙여 나중에 (5주차부터 6주차)
```
