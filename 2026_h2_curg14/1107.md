# 261107) dust-to-arc 다음으로 생각한 것

## Review: dust-to-arc

- 제 기준으로 크기가 작은 프로젝트여서 아쉬웠음.
  - 프로토타입의 핵심 지표도 회수 금액이 아니라 "Arc 첫 트랜잭션 만든 지갑 수"
  - 바꿔 말하면 사용자 한 명의 첫 트랜잭션을 운영비로 사 오는 구조
  - 프로토타입의 비용 Model: 1인당 비용

    | 사용자 유형                                  | 1인당 처리 비용 |
    | -------------------------------------------- | --------------- |
    | L2 세 체인(Base, OP, Arbitrum)만 쓰는 사용자 | 0.1709달러      |
    | Ethereum까지 네 체인을 쓰는 사용자           | 0.3823달러      |

  - 사용자 수를 늘려 보면 운영하는 쪽이 내는 돈은 이 정도임. (마지막 열은 프로토타입 규칙상 Ethereum 무료 처리 상한 0.30달러를 더한 최악의 경우)

    | 사용자 수 | L2 셋만   | 네 체인   | L2 셋 + Ethereum 상한 |
    | --------- | --------- | --------- | --------------------- |
    | 50명      | 8.55달러  | 19.12달러 | 23.55달러             |
    | 200명     | 34.18달러 | 76.46달러 | 94.18달러             |
    | 1,000명   | 170.9달러 | 382.3달러 | 470.9달러             |
    | 10,000명  | 1,709달러 | 3,823달러 | 4,709달러             |

  - 50명과 200명은 프로토타입이 적은 공개 파일럿 규모임. 외부 감사, 서버, 컨트랙트 배포 같은 고정비는 금액 자료가 없어서 넣지 않음
  - (크기가 작다는 것은 어디까지나 제 판단)
- 근탁님이 만든 부분이 대부분이고 앞으로는 다듬고 운영하는 일이 중심이라, 제가 맡을 일이 적어 보임
  - 기획의 기술 구조를 보면, 사용자가 막히는 세 Gateway을 이미 있는 부품으로 대부분 푸는 설계. 운영자가 새로 만드는 것은 릴레이어와 스위퍼 컨트랙트 정도

    ```text
    [원본 체인]  잔돈 USDC
         |
         |  Gateway 1: 꺼내려면 그 체인의 가스가 필요함
         |    -> 사용자는 서명만, 가스는 릴레이어가 대납
         v
    [체인 사이]
         |
         |  Gateway 2: 다른 체인으로 옮겨야 함
         |    -> CCTP로 소각 후 재발행, 발행 tx는 Circle Forwarding이 처리
         v
    [Arc 도착]
         |
         |  Gateway 3: 받은 돈을 쓰려면 또 가스가 필요함
         |    -> Arc는 USDC가 곧 가스라서 따로 준비할 것이 없음
         v
    [바로 사용]
    ```

## 모은 잔돈으로 무엇을 할 수 있을까

- 그래서 더 큰 프로젝트가 있으면 좋겠다고 생각
- dust-to-arc로 Arc에 도착한 Dust(소액 USDC)와 연결되는 경험에 집중
- 출발점은 "Dust(모은 잔돈)으로 무엇을 할 수 있나"
  - 지난 논의에서 정리한 흐름으로 보면,

    ```text
    다른 체인 지갑에 남은 소액
    |
    | 회수하고 모으는 가치
    v
    dust-to-arc의 도착 잔액
    |
    | 미확인: Arc에서 처음 해 보고 싶은 일
    v
    첫 사용 경험
    |
    | 미확인: 같은 앱으로 다시 올 이유
    v
    반복 참여
    ```

  - 회수한 뒤 그냥 보유하고 싶은 사람도 있을 수 있음
  - 잔돈 서비스들(Trust Wallet, Binance.US, LI.FI)도 안내는 "다시 쓸 수 있는 자금으로 바꾼다"까지이고, 그 돈으로 무엇을 하라는 안내는 없음 ([Trust Wallet Dust Cleaner](https://trustwallet.com/blog/company/dust-cleaner-unlock-more-value-from-your-wallet), [Binance.US 소액 잔고 전환](https://support.binance.us/en/articles/9842899-how-to-convert-small-balances-and-crypto-dust-to-bnb-btc-eth-or-usdt), [LI.FI Jumper](https://li.fi/knowledge-hub/how-jumper-uses-li.fi-composer-to-turn-wallet-dust-into-usable-liquidity))
- Arc에서만 할 수 있는 Agent 관련 일은 아직 찾지 못함
  - 에이전트 결제를 공개 기록에서 집계하는 Agent GDP 기준으로,
    - 최근 30일 거래액 약 37만 5천 달러 가운데
      - 약 74%(276,464달러)가 Base에서 나왔고
      - Arc는 30건에 0.19달러였음 ([Agent GDP 체인별 집계](https://agentgdp.io/api/v1/chains?range=30d))
  - Circle의 x402 서비스 목록도 비슷함. 결제를 받을 준비가 된 것과 실제로 팔린 것은 다르다는 점을 같이 봐야 함

    | 항목                                 | 수                   |
    | ------------------------------------ | -------------------- |
    | 목록 전체                            | 2,780건              |
    | Arc 결제를 받는다고 등록한 항목      | 2,182건              |
    | Arc로만 받는 항목                    | 73건(모두 한 호스트) |
    | 같은 기간 Arc에서 실제로 일어난 결제 | 30건, 0.19달러       |

    출처: [Circle x402 목록](https://api.circle.com/v2/x402/discovery/resources), [Agent GDP 체인별 집계](https://agentgdp.io/api/v1/chains?range=30d)

  - Arc에 남는 이유는 USDC로 수수료를 낸다는 점과, 도착한 잔액에서 바로 이어진다는 점 정도
  - Arc의 지금 사용처를 보면, 최근 7일 상위 8개 앱(Uniswap, KyberSwap, Archery, Morpho, 0x, Relay, rhino.fi, LI.FI)이 교환 4개, 대출 1개, 브리지 3개로 거래와 자금 이동이 중심임. 1위 Uniswap이 약 4,824만 달러임(Registrai 집계, 지갑당 앱당 시간당 1만 달러 상한을 둔 값). 리테일이 소액으로 쓸 앱은 이 목록에 잘 보이지 않음

## Dust(잔돈)을 에이전트에게 맡기는 방안

- 먼저 잔돈을 에이전트에게 맡기고 "이거 불려줘"라고 하는 방안을 생각함. 에이전트가 이 돈으로 노동자처럼 일하는 방향과, 자산을 운용하는 방향이 있음
  - 사람이 서비스를 사서 일을 맡기는 것과 에이전트가 스스로 일해서 버는 것은 다른 이야기이고, "불려줘"는 뒤쪽에 가까움
  - 지난 논의에서 정리한 기준으로, 돈을 주고받을 수 있다는 것과 실제로 벌 수 있다는 것 사이에는 단계가 여럿 있음

    ```text
    지급 기술: 돈을 보내고 받을 수 있는가
    |
    | + 구매자와 주문을 확인
    v
    유료 수요: 실제 상대가 결과에 돈을 내는가
    |
    | + 비용과 실패를 확인
    v
    지속 활동: 수입과 지원으로 운영을 이어가는가
    |
    | + 단순 규칙 및 자본 수익과 비교
    v
    판단의 기여: 에이전트가 무엇을 달리했는가
    ```

    현재 실제로 기술이 존재하고 작동됨을 확인된 것은 맨 위 단계(지급 기술)까지

### 노동자처럼 일하게 하는 방향

- 에이전트를 띄우는 일은 쉬워졌지만, 일을 찾아서 납품까지 하게 만드는 일은 여전히 어려움
  - Virtuals는 터미널 명령과 코드 없이 쓰는 콘솔을 제공하고, Pearl은 내려받아 설치하는 앱임 ([Virtuals 시작 안내](https://os.virtuals.io/quickstart), [Pearl](https://pearl.you/))
  - 이건 등록과 실행이 쉽다는 뜻이지, 일을 따내서 납품하는 과정까지 쉽다는 것은 아님
- 공개된 일감은 번역, 요약, 문서 점검처럼 글을 읽고 처리하는 일이 많고, 게시판과 대금 예치를 맡아 줄 플랫폼도 필요
  - ArcBounty 일감 16건을 종류별로 나누면 아래와 같음. 개발 일도 일부 있음 ([ArcBounty 일감 목록](https://arcbounty.app/api/v1/bounties))

    | 종류   | 건수 |
    | ------ | ---- |
    | 콘텐츠 | 5    |
    | 기타   | 5    |
    | 개발   | 3    |
    | 데이터 | 2    |
    | 디자인 | 1    |

  - 대금 예치와 검수, 이의 제기는 플랫폼이 맡고 있음 ([ArcBounty](https://arcbounty.app/))
- 직접 구성하기 싫다면 에이전트 마켓을 쓰는 방법이 있음. 마켓에서는 결과나 호출 단위로 돈을 냄
  - "에이전트가 일을 어떻게 얻는가" (아래 셋은 순서가 아니라 서로 다른 진입 경로)

    ```text
    일감과 수입을 얻으려는 에이전트
    |
    +-- 공고에 지원
    |   +-- 요구 조건을 읽고 지원, 수락
    |   +-- 수행하고 검수와 지급 확인
    |
    +-- 서비스를 등록
    |   +-- 제공할 결과와 조건 게시
    |   +-- 주문을 받아 수행하고 지급 확인
    |
    +-- 호출 단위로 판매
        +-- 유료 기능을 공개
        +-- 요청 처리와 지급 확인
    ```

  - 어느 쪽이든 LLM API 비용을 넘겨서 일을 시키는 구조는 아님. 모델 사용료는 판매자가 부담하거나 따로 협의해야함
    - Agentalent는 운영자와 회사가 정한다고 안내함
    - ([Virtuals ACP 판매 절차](https://os.virtuals.io/acp/cli/provider-workflow), [OKX.AI 에이전트](https://www.okx.ai/agents), [Agentalent FAQ](https://agentalent.ai/builder-faq))
- 즉 절차와 결제 수단은 이미 있는데, 돈을 내고 일을 맡기는 수요는 확인하지 못함
  - 공고에 지원하는 곳: 외부 발주가 꾸준히 이어지는 곳이 없었음

## 그래서 생각한 것: 했졔

- 방향을 바꿔서 예측 시장에 가까운 아이템을 생각함
  - "도박에 가까운 예측 시장"
  - 비교할 만한 서비스로 Predictoor(예측 봇과 자금 재분배), Polymarket(결과 판정 절차), AfterHour(실제 포지션과 게시물 연결)가 있음
    - ([Predictoor](https://docs.predictoor.ai/earn-predictoor), [Polymarket 결과 판정 방식](https://help.polymarket.com/en/articles/13364518-how-are-prediction-markets-resolved))
  - 차별점은 잔돈 회수 다음의 첫 경험, 사람의 발언과 대결, 선택형 에이전트, 쌓이는 전적을 하나로 묶는다는 것

    ```text
    했졔 원안: 발언, 참가금, 결과
    |
    +-- BTC 가격을 넣은 번호 추첨
    |   +-- 검토만 하고 남겨 둠
    |
    +-- 공동 상금 없는 소액 현물투자 기록
    |   +-- 사용자가 큰 그림과 참여 동기를 요구해 정정
    |
    +-- 공동 상금, 시즌, 커뮤니티를 살린 아레나
        +-- 사용자가 큰 그림에 긍정
        |
        +-- 실제 거래와 배당을 함께 검토
        |   +-- 실자금 운영의 조건은 미확인
        |
        +-- 현재: 사람 중심의 테스트넷 실험
            +-- AI는 선택형 대리 참가
    ```

- 적은 돈으로 살 수 있는 것은 있어도, 불리기는 어려움
  - OKX.AI의 에이전트 서비스는 0.01 USDT부터 있고, x402 유기적 거래는 건당 평균 약 0.068달러라서 1달러면 14번 남짓 호출할 수 있음 ([OKX.AI 에이전트](https://www.okx.ai/agents), [Agent GDP 전체 현황](https://agentgdp.io/api/v1/overview))
  - 다만 그 호출이 쓸 만한지, 잔돈을 가진 사람들이 이런 소액 구매를 원하는지는 별개 문제
- 그래서 자기 예측에 작은 돈을 걸고, 다른 사람과 겨루고, 그 기록을 남기는 재미를 앞세우려 함
  - 사람들이 낮은 확률을 실제보다 크게 느끼고 복권 같은 보상을 좋아한다는 연구가 있음. 다만 이건 경향이지 모두의 본성은 아님 ([Barberis, 전망 이론 30년](https://www.nber.org/papers/w18621))
  - 지금 설계는 큰 보상을 노리는 구조가 아님. 맞힌 쪽은 `총 풀 * 내 참가금 / 맞힌 쪽 참가금 합계`를 받음(내 참가금 포함)
  - 맞다에 4, 아니다에 6이 모였을 때 1을 건 사람이 받는 돈은 아래와 같음

    | 결과          | 1을 건 사람이 받는 돈     | 늘어난 돈 |
    | ------------- | ------------------------- | --------- |
    | 맞다가 적중   | (4 + 6) * 1 / 4 = 2.5     | +1.5      |
    | 아니다가 적중 | (4 + 6) * 1 / 6 = 약 1.67 | 약 +0.67  |
    | 틀린 쪽       | 0                         | -1        |

    양쪽이 비슷하게 모이면 2배 안팎이라, 큰 보상보다는 겨루는 재미를 이유로 둠. 운영수수료는 기본안에 없음

- 가장 큰 문제는 법. 참가금을 모아 결과에 따라 나누는 구조는 나라마다 도박이나 금융 규제 대상이 될 수 있음

  | 지역      | 쟁점                                                                                                    | 근거                                                                                                                                                                                                                                                                                 |
  | --------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
  | 한국      | 형법의 도박장소 개설죄(제247조), 복표 발매죄(제248조), 해외에서 한 행위에도 적용되는 내국인 국외범 조항 | [제247조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020147721), [제248조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=1000976697), [국외범 조항](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=1000792521) |

  - 쟁점을 정리한 것이고 법률 의견은 아님
- 그래서 진행한다면, 우선 무료 테스트 USDC로, 사람들이 게임을 이해하고 다시 찾아오는지부터 테스트 할 수 있음. 실제 참가비, 환전, 현금성 보상은 연결하지 않음
  - 테스트 USDC는 Circle이 무료로 나눠 줌 ([Circle 테스트넷 파우셋](https://faucet.circle.com/))
  - 테스트넷이라고 법적으로 면책되는 것은 아님. 영국 도박 감독기관은 현금으로 바꾸거나 거래할 수 있는 게임 아이템을 가치 있는 것으로 봄 ([영국 도박위원회 안내](https://www.gamblingcommission.gov.uk/licensees-and-businesses/guide/page/digital-and-virtual-currencies))
- 이름은 "했졔", 영문명은 "as I told you". 정해진 회차마다 가격을 예측해서 참가하고, 맞힌 쪽이 배당을 받음
  - 기본 경기는 정해진 시각의 BTC 가격이 기준가 이상인지를 맞다, 아니다로 고르는 형식임. 가격 출처, 마감과 판정 시각, 무효 규칙은 참가 전에 고정함
  - 마감 때 한쪽에만 참가금이 있으면 모집 실패로 전액 환불하고, 가격을 판정할 수 없으면 무효로 환불함
  - 아직 구현하거나 배포하지는 않음
- 예측과 결과를 기록으로 남기고, 사람들이 그 기록을 두고 이야기하게 해서 커뮤니티를 만들고 싶음. 이 부분은 아직 고민 중
  - 설계에서 그리는 한 경기의 흐름은 아래와 같음.
    - P와 Q는 참가자
    - G는 같은 조건의 경기
    - R은 전적과 커뮤니티 기록
    - 화살표는 행동이나 기록의 전달

    ```text
    P          G          Q          R
    |          |          |          |
    |--------->|<---------|          |  각자의 방향과 금액으로 참가
    |          |          |          |
    |<---------|--------->|          |  조건과 분포를 보며 토론
    |          |          |          |
    |          |-------------------->|  판정과 참가 기록을 연결
    |          |          |          |
    |<-------------------------------|  원래 발언과 결과를 확인
    |          |          |          |
    |--------->|<---------|          |  다음 경기에서 다시 대결
    ```

  - 다시 올 이유로 기대하는 것은 배당만이 아님. 지난번에 맞힌 사람이 이번엔 뭐라고 하는지, 반박했던 상대는 어떻게 됐는지, 이번 시즌에 누가 앞서는지를 보는 재미임
- 베팅에는 에이전트도 섞으려 함. 중심은 사람의 예측과 대결이고, 에이전트는 사용자가 고르는 선택 기능임
- 사용자는 에이전트의 제안을 보고 직접 참가하거나, 정해 둔 한도 안에서 에이전트가 대신 참가하게 할 수 있음. 전적에는 직접 참가와 대리 참가를 구분해서 남김
  - 설계상 역할 분담은 아래와 같음. 에이전트는 개인키를 받지 않고, 별도 실행기가 한도와 경기 조건을 확인한 뒤에만 참가함

    ```text
    아레나
    |
    +-- Arc 계약
    |   +-- 고정된 경기 조건
    |   +-- 참가금과 사용자별 지급 권리
    |   +-- 판정, 무효, 수령 상태
    |
    +-- 서버
    |   +-- 예측글 원문과 수정 이력
    |   +-- 댓글, 프로필, 커뮤니티 화면
    |   +-- 체인 기록을 읽어 만든 조회 데이터
    |
    +-- AI 실행기 (선택)
        +-- 자료를 읽고 판단한 이유
        +-- 사용자 한도 확인 후 승인된 범위에서만 실행

    공유하는 연결: 경기 식별자와 발언 식별 기록
    ```

    방향과 금액, 이유를 제안하는 것은 AI이고, 실제 참가는 실행기가 한도를 확인한 뒤에만 함

  - 참가할 때마다 직접 실행인지 AI 대리 실행인지 기록하고, 전략을 바꿔도 이전 기록을 덮어쓰지 않음
  - LLM 사용료는 테스트 USDC와 별개로 실제 비용이 들 수 있음
