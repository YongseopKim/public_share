## [Agent Payment 한눈에 보기](1015/agent-payment.md)

```text
[지금]        사람 ---- 직접 결제 ----> 가맹점     결제하는 쪽 = 책임지는 쪽
[Agent 시대]  결제하는 쪽(Agent) != 책임지는 쪽(사람)
              결제의 단위: 사람 하나  ==>  사람 + Agent + 위임 범위 (6.1)

  [풀림] = 가상카드로 이미 풀림     [안 풀림] = 가상카드로 풀리지 않음     ? = 열린 질문

  사람: 책임을 진다
  |   지금은 이 사람 하나가 결제 시스템의 단위 (4.1)
  |   본인 확인, 결제 순간의 인증, 사기 탐지, 분쟁 처리가 모두 사람에 묶여 있음
  |
  |   맡긴다: 위임 범위 = 한도, 용처, 기간
  |   - 4.2 Agent가 판단하므로 거래마다 미리 승인할 수 없음
  |   - 4.3 [풀림] Agent마다 범위를 따로 정하고 빨리 주고 거두기 (5.1 가상카드)
  v
  Agent: 무엇을, 언제, 얼마에 살지 스스로 판단 (2.1)
  |   - 2.2 판단 없는 자동화(정기배송, 자동이체)는 Agent가 아님
  |   - 3   리테일, 데이터 구매, 클라우드 자원 Agent가 같은 결제 기술을 씀
  |   - ?   판단의 정도: 어디까지 Agent가 정하는가 (7)
  |
  |   결제 + "위임받았다"는 증명   <== 이 연결이 Agent Payment (3)
  |   - 5.2 [안 풀림] 건당 비용: 아주 작은 결제에 고정 수수료가 붙음
  |   - 5.2 [안 풀림] 결제 순간의 인증: 3DS, OTP는 사람이 있어야 통과
  v
  가맹점: 위임을 확인한다
      - 5.2 [안 풀림] 이 Agent가 정말 사람에게서 위임받았는가

  구조 전체에 걸리는 것
      - 5.2 [안 풀림] 책임: 잘못된 결제는 누가 지는가 (? 7)
      - ?   어느 시장이 먼저인가: 소비자 구매인가, 기업 간 거래인가 (7)

  ------------------------------------------------------------------------
  밑에 깔리는 결제 수단: 어느 길로 나올지 아직 모름 (6.2)
      카드 시스템을 고쳐 쓰는 길   <-- 서로 끌어들임 -->   Agent용 새 시스템
      비자 TAP, 마스터카드 Agent Pay                스테이블코인, x402, Nanopayments
```
